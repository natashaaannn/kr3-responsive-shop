# SpookyShop — контрольная работа №3

**Тема:** «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

SpookyShop — учебный магазин товаров для Хэллоуина на HTML, CSS и JavaScript. Проект создан на основе КР №1, без Bootstrap и других CSS-фреймворков.

- [Открыть сайт через GitHub Pages](https://natashaaannn.github.io/kr3-responsive-shop/)
- [Репозиторий](https://github.com/natashaaannn/kr3-responsive-shop)

## Страницы

| Файл | Назначение |
|---|---|
| `index.html` | Главная страница: приветственный блок, преимущества, популярные товары |
| `catalog.html` | Каталог из 18 товаров и фильтры по категориям, статусу и цене |
| `product.html` | Костюм скелета: изображение, описание, цена и характеристики |

| `contacts.html` | Контакты, Яндекс.Карта, форма обратной связи и окно обратного звонка |

## Практическое занятие №12 — адаптивная вёрстка

- `css/responsive.css` подключён **после** `css/style.css` на всех пяти страницах; на каждой странице есть `viewport`.
- Использованы Mobile First, медиазапросы, CSS Grid и Flexbox. Основные контрольные ширины: **360, 430, 768, 1024, 1440 px**.
- На телефоне карточки товаров идут в одну колонку, от 640 px — в две, от 1024 px — в три.
- На узких экранах фильтры располагаются над каталогом; на десктопе — слева от товаров.
- На странице товара описание располагается под изображением на телефоне и справа от него на десктопе.
- Форма заказа и обратной связи на мобильных экранах расположена в одну колонку; на широких экранах часть полей перестраивается в две.
- Размеры изображений ограничены шириной контейнера; для товаров используется `srcset`, `sizes`, а также `picture` с WebP и запасным PNG.
- Таблица характеристик сохраняет табличный формат на широких экранах; на мобильных заменяется карточками.
- Модальное окно ограничено размером экрана, его содержимое прокручивается при необходимости.

## Практическое занятие №13 — доступность

- На всех страницах есть один `h1`, семантические `header`, `nav`, `main`, `section` и `footer`.
- Добавлена ссылка «Перейти к основному содержимому»; основной блок имеет `id="main"` и `tabindex="-1"`.
- Активные страницы в меню обозначены `aria-current="page"`.
- Фокус при управлении клавиатурой выделяется через `:focus-visible`.
- Изображения товаров имеют осмысленные `alt`, поля форм — связанные `label`.
- Улучшена контрастность оранжевых кнопок и значков товаров.
- Модальное окно использует нативный `dialog`, имеет заголовок и закрывается клавишей Escape.
- Добавлена поддержка `prefers-reduced-motion`; для повышенного контраста — `prefers-contrast: more`.
- Встроенной карте добавляется `title`, когда внешний скрипт создаёт `iframe`.
- При проверке формы ошибки отмечаются через `aria-invalid`, а результат появляется в области `role="status"`.

### Проверка адаптивности

Локально проверена структура HTML/CSS/JS в Chromium на **25 сочетаниях**: пять страниц × 360, 430, 768, 1024, 1440 px. В проверке подтверждены отсутствие общего горизонтального переполнения, переключение мобильного меню, фильтрация товаров, сброс фильтров, адаптивные характеристики товара и открытие/закрытие модального окна.

В браузере после публикации дополнительно проверьте внешний скрипт Яндекс.Карт, изображения и формы, а также повторите Lighthouse. Внешняя карта зависит от доступности сервиса Яндекса.

### Финальная проверка кода перед сдачей

- Удалены неиспользуемые CSS-правила, переменная и пять неиспользуемых фоновых PNG; рабочие изображения и их версии `srcset` сохранены.
- У изображений карточек добавлены реальные `width` и `height` для резервирования места до загрузки.
- В таблице характеристик добавлены `scope="col"` и `scope="row"`.
- Исправлена обработка неверного диапазона цен: фильтры не сворачиваются, пока пользователь не исправит ошибку; при вводе корректного значения ошибка сбрасывается.
- Формы теперь снимают предыдущие сообщения об успешной проверке при новом вводе; у формы обратной связи ошибки также отмечаются через `aria-invalid`.
- Повторно выполнены автоматизированные проверки разметки и сценариев в Chromium на всех пяти контрольных ширинах. Сохранённые в `lighthouse/` снимки относятся к предыдущему аудиту, поэтому перед сдачей нужно заново запустить Lighthouse для окончательной версии.

### Как проверить самостоятельно

1. Откройте сайт в Chrome и включите DevTools → режим устройства.
2. Проверьте 360, 430, 768, 1024, 1440 px: меню, каталог, фильтры, карточки, форму, таблицу и подвал.
3. На 360 px откройте «Меню», пройдите по ссылкам клавишей Tab, закройте через Escape.
4. В каталоге разверните фильтры, выберите тип товара, нажмите «Применить», затем «Сбросить».
5. На `product.html` проверьте карточное представление характеристик на телефоне и таблицу на десктопе.
6. Во вкладке Network → Img посмотрите, что Chrome выбирает WebP; во вкладке Elements проверьте `currentSrc`.
7. На странице контактов откройте окно обратного звонка с клавиатуры и закройте Escape.
8. Запустите Lighthouse → Accessibility на всех пяти страницах и обновите скриншоты при необходимости.

## Запуск

1. Скачайте репозиторий и откройте папку проекта в VS Code.
2. Запустите `index.html` с помощью Live Server.
3. Для адаптивной проверки используйте Chrome DevTools.

Серверной обработки заказов нет: формы выполняют учебную проверку введённых данных и показывают локальное уведомление, но **ничего не отправляют на сервер**.
